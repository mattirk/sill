## Method

Five code reviews in parallel, each reading its area end to end and re-checking the earlier audit's
claims against the current code:

1. the jail escape surface (`jail.rs`, `seccomp.rs`, `launcher.rs`, `sill-shim`, the default policy);
2. network egress, agent installs and credentials (`proxy.rs`, `registry.rs`, `login.rs`);
3. host-side consumers of agent data (Changes, Keep, workspaces, `sill-gui`);
4. the root install, the daemon and its protocol, Host control, remote boxes, the release pipeline
   and `site/install.sh`;
5. the Mac app and its VM (`sill-vm`, the Mac grants, the guest image), audited here for the first
   time alongside the "Security review from a jail" in `sill-mac.md`.

Plus a live probe from inside a running jail (a session in Sill.app's arm64 VM), marked ⊙. The
findings rated High and the regressions were then re-read in the code by the coordinating reviewer;
those are marked ✓. Read-only: nothing was built, exploited or changed.

**Confidence.** *Confirmed*: the code path was read end to end (and seen live where ⊙).
*Likely*: the code is confirmed but the result rests on kernel, bubblewrap, git or macOS behaviour
that was not tested. *Speculative*: a step is unverified and named.

**Threat model.** As on 2026-11-01: (a) the agent in the jail is fully hostile; (b) a second
unprivileged local account; (c) the person runs `sill init` from a checkout an agent could have
modified. Added: (d) a network attacker, a hostile remote box, or a hostile or compromised agent
registry; (e) on the Mac, an agent that has left its jail and controls the VM account or the guest.

## Summary

- **The jail's own construction holds.** No capabilities, no nested user namespaces, an empty
  network namespace, a cleared environment, fresh `/run` `/tmp` `/proc` `/dev`, no host bus or
  display, shim sockets unreachable, descriptor hygiene (⊙). The proxy's allow-list matching and
  address checks hold. The fixes for S1–S11, S13–S16 and S21 hold, with the residuals listed below.
- **Four High findings**, all outside the bwrap argv itself: a login button that runs a freshly
  installed agent package on the host unjailed (A1); the state filesystem readable from every jail
  in Sill.app's VM, which exposes other sessions' files and other agents' logins (A2); host mounts
  made after a jail starts arriving writable in its host view (A3); and a host write through an
  agent-controlled path in workspace Discard/Undo (A4).
- **Two regressions against the 2026-11-01 audit:** "Keep all" is unfiltered again (A5, was S10),
  and the `NoNewPrivileges` that S18 records on session units is not in the code (A19).
- **The Mac VM is a weaker second wall than the document set implies:** no seccomp on arm64 (A9),
  shares read-write to the whole VM (A14), and Mac-side trust in what the guest's daemon says (A8,
  A12, A23).
- **Things the person grants are wider than their names:** `launch` equals `commands` (A16),
  "Control Mac" can operate Sill's own switches (A13).

## What holds

- ⊙ Capabilities empty in every set; `NoNewPrivs: 1` from bwrap; nested user namespaces refused;
  own mount, pid, ipc, uts, cgroup and network namespaces; `lo` only, no route, no DNS.
- ⊙ `/run`, `/tmp`, `/proc`, `/dev` fresh; no host bus, X11 or Wayland in a default jail; the root
  is remounted read-only last; `--clearenv` with an explicit allow-list.
- ⊙ Shim: control socket is an inherited descriptor with no path, the shim is non-dumpable, its
  `/proc/<pid>/fd` is unreadable; revert is symlink-proof and overlay-only.
- Agent homes, workspace clones and rules inside pins are opened with `openat2(NO_SYMLINKS)` and
  bound by descriptor; a mask path containing a link fails the launch.
- Proxy: a Unix socket per session, invisible to other sessions; suffix match on a `.` boundary;
  DNS on the host only after the name passes, every address checked, the connection goes to the
  checked address; local and reserved ranges refused before the allow-list; header, line and
  connection caps; only `host:port` logged.
- Keys and logins: 0600 files in 0700 directories under the masked state directory; agent
  definitions under the masked `~/.config/sill`; host login for declared agents runs in a private
  scratch home and copies back only declared files beneath it.
- Keep: `openat2` beneath and no links for source and parent, `O_EXCL|O_NOFOLLOW` destination,
  hash of the copied bytes, setuid stripped; SQL fully parameterised.
- Terminal widget: OSC 52 and title changes are dropped; clipboard writes only on the person's copy.
- Daemon socket: 0600 in a 0700 directory, peer uid checked, frame and queue caps, single-use
  256-bit stream tokens.
- Host control: activation only over the daemon socket, never by policy default, in memory only;
  the agent's bridge is in a read-only directory; generation and operation checked under the gate.
- SSH to boxes: argv with `--`, hostile host names refused, no box-supplied file content written
  on the desktop.
- Root install: per-uid directory handling as fixed for S5; unit and binary writes by rename into
  root-owned directories; deb postinst runs only `sill init`.
- Workflows: `contents: read` by default, no `pull_request_target`, no secrets reachable from pull
  requests, release tag validated, releases are drafts until a person publishes.
- Mac: the guest is reached over vsock only; the SSH key is generated per Mac, none is baked into
  the image; the Mac request port needs a per-boot 256-bit token and the window's own record of the
  grant; commands are spawned without a shell with a canonicalised starting directory; the only
  entitlement is virtualization, with the hardened runtime.

  short root test on a real host; A4's race and A15's git behaviour were not run; nothing was run
  on a Mac outside the VM.
- ACP message handling (`acp.rs`, `acp_v2.rs`), the relay, and the roughly 150 `_sill/*` methods as
  a parsing surface; a panic there exits the daemon by design.
- sill-gui's markdown renderer, editor, drag and drop and notifications; registry SVG icons rendered
  with resvg.
- `workspace/records.rs`, `carry.rs`, the crosscheck daemon side, `sill-memory`'s reader.
- Whether a jail can open `AF_VSOCK` to the Mac's port or the guest's sshd (the probe was refused).
- The TUI as a client of a hostile box; `publish/export.sh`.

## Proposed order

1. **A1**: require `host_login` for the setup path too, or run setup logins in a jail; correct the
   schema text.
2. **A2, A3**: exclude the state filesystem by device, not by path; make the host view private
   (no propagation) or cover its mount points against later mounts.
3. **A4, A5**: write `HEAD` through `safe_fs` beneath the clone; restore the Keep-all filter in the
   daemon, not in the client.
4. **A6, A7, A8**: confine `cmd`, restrict curl to `--proto =https` with `--`, check the scheme on
   the desktop before opening.
5. **A9, A19**: an aarch64 seccomp filter; either add the hardening S18 records or correct the record.
6. **A10**: widen the default masks. Then the Mac items (A12–A14, A23) and the release chain (A18).
